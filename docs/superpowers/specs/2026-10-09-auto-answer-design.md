# 华工实验室安全自动答题扩展设计

> 本设计取代 `2026-10-09-offline-safety-quiz-design.md`。最初一版曾按复旦 `lsem.fudan.edu.cn`（iCheck 控件、分页答题）实现，目标站点改为华工 `zhsys.sb.scut.edu.cn` 后整体重写。

## 目标

在 `safetest` 目录提供一个可直接通过 Chrome“加载未打包的扩展程序”安装的自动答题扩展：在华南理工大学实验室安全综合管理系统打开试卷后，按本地题库自动勾选答案，**不自动交卷**，由人工核对后提交。

## 范围

包含：

- 声明 `zhsys.sb.scut.edu.cn` 的 host 权限，向该站点注入 content script。
- 权限为 `activeTab` + `storage` + `scripting`；`scripting` 仅用于在页面早于扩展加载时补注入 content script。
- 按题干匹配本地题库，勾选单选、多选与判断题的答案。
- 右上角状态面板显示进度、已作答/跳过数量与跳过原因。
- 把 `../tiku.txt` 转换成扩展题库的脚本 `tools/build_bank.py`。

不包含：

- 自动交卷或任何形式的提交。
- 读取页面内已下发的正确答案字段（见下节）。
- 课程学习、题库管理等其它平台功能。

## 答题依据的选择

试卷页的 `AnswerForm` 组件里存在这样的逻辑：

```js
answer(){
  if(this.form.type===1){ const t=this.form.options.findIndex(e=>e.rightAnswer); return t>=0?A[t]:"" }
  ...
}
```

即选项对象上的 `rightAnswer` 字段。这些对象来自 `POST /exam/test/start/{id}` 的响应，理论上若服务端在考试期间一并下发，答案就存在于页面内存中，可通过注入主世界脚本捕获响应取得。

**本设计不采用这条路**，改为题干匹配本地题库。原因是这与“使用公开题库辅助”性质不同，二是题库方案不需要注入主世界脚本，权限与实现都更简单。

## 页面结构与耦合点

目标站点是 Vue 3 + Element Plus 的 hash 路由 SPA，全部题目渲染在同一页，左侧题号导航、右侧滚动。以下结构来自试卷页懒加载分包 `do-*.js` 与 `answer-form-*.js`：

```text
.question-bottom-line[.test-questions]     每道题，id=question-N
└─ .qeustion-item-box
   └─ .question-content
      ├─ .question-title                   题干（HTML）
      └─ .question-options
         单选 → .el-radio-group    label.el-radio    → input.el-radio__original[value=选项id]
         多选 → .el-checkbox-group label.el-checkbox → input.el-checkbox__original[value=选项id]
         判断 → .el-radio-group    两个 radio：value="true"(对) / value="false"(错)
```

- 题型由 DOM 推断：有 `el-checkbox-group` 即多选；两个 radio 且值为 `true`/`false` 即判断；否则为单选。
- **选项靠文本比对，不靠字母**。`input` 的 `value` 是选项 id，字母只是渲染时的下标映射，且选项顺序可能被打乱。
- 选择动作是点击 `input.el-radio__original` / `input.el-checkbox__original`，触发 Vue 的 v-model；选中态读 `input.checked` 或 `label.is-checked`。
- 提交按钮的文案是“提交试卷”，代码中不匹配、不点击。

## 题库来源与格式

题库由 `tools/build_bank.py` 从 `../tiku.txt` 生成。该文件里并存**两套格式**，两者互不重叠：

| | 格式 A（前半部分） | 格式 B（后半部分） |
|---|---|---|
| 题头 | `58、[单选题] 题干 （分值1.0）` | `1 多选题 题干`（无方括号、无分值） |
| 选项 | `• A. 文本` 逐行 | `A 文本`，空格分隔，可能整段挤在一行 |
| 答案 | `你未作答 标准答案： B` | `正确答案： A,B` |
| 多选 | 无 | 支持，逗号分隔字母 |

格式 B 的题目常常整段挤在一行（一行的长度可达上万字符），因此解析必须用全文正则而非逐行匹配：

```python
r"(\d+)\s+(单选题|判断题|多选题)\s+(.*?)正确答案\s*[:：]\s*([^\s]+)"
```

选项的切分同样不能依赖换行：用“字母两侧都是空白，且必须按 A、B、C… 依次出现”作为边界，避免题干里的“维生素A.”之类被误判。

产出 2776 道唯一题（单选 939、多选 389、判断 1448），其中 442 条来自人工/模型作答的补充题库 `asset/extra.json`（见 `tools/import_answers.py` 与 `tools/import_paper_answers.py`）。多选条目带着多个正确选项文本，作答时全部勾选。

## 匹配算法

题干与题库都做同一套归一化（全角转半角、统一引号、**去掉 `()` 空占位符**、去空白、去题号前缀），再算 Levenshtein 相似度。

去空占位符这一步是踩过坑补上的：试卷题干常写成 `…正确的是?()`、`…错误的是:()。`，而题库里对应的是 `…正确的是?`、`…错误的是:`。多出的 `()` 让长度差超出预过滤允许的范围，导致**题库里明明有的题匹配不到**。用两套真实试卷回归，这一条就救回了 10 道题。`tools/build_bank.py` 与 `extension/content.js` 各实现一份，规则必须保持一致。

长度差本身就超过阈值允许编辑距离时直接跳过计算，避免全库扫描过慢。

### 为什么需要“最佳/次佳间距”

题库中存在「一字之差、答案相反」的题：

| 题干 A | 题干 B | 相似度 | 答案差异 |
|---|---|---|---|
| …下咽的强酸，先饮用大量水，再服用 | …下咽的强碱，先饮用大量水，再服用 | 0.96 | 氢氧化铝溶液 / 乙酸果汁 |
| 压力表指示的压力值为绝对压力。 | 压力表指示的压力值为相对压力。 | 0.93 | 错误 / 正确 |
| 以下几种气体中，最毒的气体为 | 以下几种气体中，有毒的气体为 | 0.93 | 光气 / 氯气 |
| 实验解剖用过的污染动物尸体，应 | 实验解剖用过的无污染动物尸体，应 | 0.94 | 灭菌后处理 / 直接处理 |
| 引发电气火灾的初始原因 | 引发电气火灾的初始原因是 | 0.92 | 绝缘老化 / 过电流 |

仅靠阈值无法区分：把阈值提到 0.96 会同时砍掉大量正常匹配，而危险配对最高正是 0.96。因此判据改为：

```js
best.similarity >= 0.92  &&  best.similarity - second.similarity >= 0.02
```

即最佳匹配必须明显领先次佳匹配，否则整题跳过。选项目标文本的模糊回退也套用同一判据（没有“正确答案”可比，维持严格版）。

在这条基本判据之外还有两条同样原则性的放宽，用来避免白白丢覆盖率：

1. **按题型分池匹配**。页面上的题型由 DOM 确定（`el-checkbox-group` → 多选；两个值为 `true`/`false` 的 radio → 判断；否则单选），所以只让题目在同题型池内竞争。跨题型条目不再互相干扰，候选数也更少。
2. **次优解答案相同则采纳**。题库里存在只差一两个字的近义题干（如“⋯移到通风良好的环境⋯”与“⋯环境中⋯”），答案完全一致。此时选哪个结果都一样，没必要因为间距小于 0.02 就跳过。判据因此变为：

```js
best.score >= 0.92  &&  (best.score - second.score >= 0.02
                         || answersEqual(best, second))
```

全库校验（见验证一节）：全部可作答，39 组危险题对双向 78 次呈现零选错。

## 数据流

`popup.js` 点击后先把时间戳写入 `chrome.storage.local.safeTestAutoRun`，再向当前标签页发送 `SAFE_TEST_AUTO_ANSWER_START`，按三步降级：

1. 页面上已有 content script 在监听 → 直接开始。
2. 在站点上但没有监听者（页面在扩展安装/重载之前就打开了，旧 content script 已被回收）→ 用 `chrome.scripting.executeScript` 手动注入一次再通知。
3. 不在站点上 → 把标签页导航到 `#/home/exam/index`。

**第 2 步失败时绝不跳转。** 用户此刻正看着站内页面（很可能就是试卷），跳转过去会把页面冲掉。这种情况只提示刷新，并清掉运行标记。

这个降级链是修 bug 加的：此前只做第 1 步和第 3 步，于是在“页面早于扩展加载”的标签页上点扩展，消息发不通就直接跳到考试列表，表现为“点击后跳回主网页”，且同一份代码在另一个正常加载的标签页上却工作正常。

由于是 hash 路由，站内跳转不会重新加载页面，content script 也不会重新注入。因此 `runExam()` 在找不到题目时不会立即失败，而是轮询等待最多 10 分钟，让用户有时间在平台里点开试卷。

页面完整加载时，content script 读取 `safeTestAutoRun`，若在 10 分钟内则自动执行 `runExam()`。

## 错误处理

- 题库读取失败或过滤后为空 → “题库为空或格式不正确”。
- 题干为空或整题是图片 → 跳过。
- 最佳匹配低于阈值 → 跳过，提示最高相似度。
- 最佳与次佳过于接近 → 跳过，提示两者分数。
- 题库题型与页面题型不一致 → 跳过（防止单选答案被套到判断题上）。
- 页面上找不到对应选项、或点击后页面未确认选中 → 跳过。
- 超过 300 题 → 抛错停止。
- 任何异常都会清理运行标记并以红色面板显示原因，避免刷新后反复重试。

跳过的题目保持空白，绝不猜测。

## 验证

`extension/content.js` 被真实加载进 Node（桩件顶替 `chrome` / `document`）后测试，而不是另写一份复制品：

1. **题库自洽**：全部 2776 题的正确答案都能在选项表中找到。
2. **匹配判据**（`margin.js`）：全部可作答；39 组危险题对双向 78 次呈现零选错；强酸/强碱混合题干判为跳过。
3. **端到端**（`harness.js`，jsdom 搭出仿真考试页）：
   - 选项顺序被打乱的单选题仍选中正确项（验证按文本匹配）
   - 判断题答案是“错” → 勾选 value=`false`；是“对” → 勾选 `true`
   - **多选题**：选中全部正确项，并清掉扩展介入前已被选中的错误项
   - 带题号前缀和多余空格的题干仍能匹配
   - 题库未匹配的题保持空白
   - 跑完后面板给出两个导出按钮，txt 版**不含**扩展自己的答案，json 版记录实际选中的选项
   - 全程从未点击“提交试卷”按钮
4. **启动分支**（`popup.test.js`）：脚本已在监听 / 站点上但脚本失效（补注入）/ 补注入也失败 / 不在站点上，四条分支各自的行为；重点是站点页面启动失败时**不跳转**。
5. **语法**：`node --check`，两个 JSON 用 `python3 -m json.tool` 校验。

需要人工完成的部分：在 Chrome 里加载扩展，确认权限只显示 `zhsys.sb.scut.edu.cn`，登录后在真实试卷上核对结果。
